## 2. 算法

### 2.1 总体：为什么是 IC-GN + ZNSSD

严格按 R1-O1 §2.2/§2.6：

- **优化目标用 ZNSSD**（最小二乘形式，直接接 Gauss-Newton），**对外报告 ZNCC**，二者由 `C_ZNSSD = 2(1 − C_ZNCC)` 互转，只算一次。
- **逆合成（inverse compositional）**：warp 增量施加在参考子区上，于是 `∇f`、`∂W/∂p`、Hessian 与其 Cholesky 分解**全部与 `p` 无关，每个 POI 只算一次**。这是 IC-GN 相对 FA-NR 的根本加速来源（Pan, Li & Tong 2013）。
- **一阶（仿射）形函数**，`p = (u, u_x, u_y, v, v_x, v_y)`。

### 2.2 逐步推导（与代码一一对应）

记参考子区局部坐标 `Δx = (Δx, Δy)`，`|Δx|, |Δy| ≤ r`，`N = (2r+1)²`。

**预计算（每 POI 一次）**

```
f_i   = f(x₀ + Δx_i)                        参考子区灰度
f_m   = mean(f),   Δf = ‖f − f_m‖₂
J_i   = [f_x, f_x·Δx, f_x·Δy, f_y, f_y·Δx, f_y·Δy]_i      (1×6，最陡下降图)
H_raw = Σ_i J_iᵀ J_i                        (6×6)
H     = (2/Δf²)·(H_raw + λ·tr(H_raw)/6·I)   λ = 1e-9（对角加载，防病态）
L     = cholesky(H)                          缓存
```

**每次迭代**

```
1. 采样  x_i = x₀ + Δx_i + u + u_x·Δx_i + u_y·Δy_i
        y_i = y₀ + Δy_i + v + v_x·Δx_i + v_y·Δy_i
        g_i = 双三次 B 样条采样(目标图, x_i, y_i)
2. g_m = mean(g),  Δg = ‖g − g_m‖₂
3. 残差  e_i = (f_i − f_m) − (Δf/Δg)·(g_i − g_m)
4. 右端  b   = (2/Δf²)·Σ_i J_iᵀ e_i
5. Δp   = −H⁻¹ b                （Cholesky 前代/回代）
6. 更新  W(p) ← W(p) · W(Δp)⁻¹  （3×3 齐次矩阵，闭式逆）
7. 收敛判据（下）
```

第 3–5 步的符号与因子是这样定出来的（R1-O1 §2.6 只给了结论，这里补上推导，供 Round 3 复核）：令
`r_i = (f_i − f_m)/Δf − (g_i − g_m)/Δg`，线性化后
`C(Δp) = Σ_i ( r_i + J_i Δp / Δf )²`，
`∂C/∂Δp = 0  ⟹  (2/Δf²)(Σ J_iᵀJ_i) Δp = −(2/Δf²) Σ J_iᵀ (Δf·r_i)`，
而 `Δf·r_i = (f_i − f_m) − (Δf/Δg)(g_i − g_m) = e_i`。故 `H Δp = −b`，`Δp = −H⁻¹b`。`2/Δf²` 在两边同时出现、其实可以约掉，代码里仍显式保留，因为同一个 `H_raw` 还要用于协方差（§2.6），保持因子可见比省两次乘法更值。

**收敛判据**（R1-O1 §2.6 的尺度化范数，把梯度分量按 subset 半径折算成"子区边缘处的位移"）：

```
s = (1, r, r, 1, r, r)
ζ = ‖Δp ⊙ s‖₂  < conv_tol   （默认 1e-4 px，比规格的 1e-3 收紧了一档）
```

规格给的默认是 `1e-3`；实测把它收到 `1e-4` 只多花约 1 次迭代（平均 4.18 次），却让残余的求解器截断误差彻底低于插值偏差，因此把默认值定在 `1e-4`。这是本实现相对规格唯一的默认值改动，已在此声明。

### 2.3 插值：双三次 B 样条（Unser 预滤波）

规格 §2.10 选 `BICUBIC_BSPLINE` 为默认。实现要点：

- **系数预解一次**：B 样条基不是插值基，必须先解 `Σ_k c_k B(x−k) = f(x)`。用 Unser 的因果/反因果递归，单极点 `z₁ = √3 − 2 ≈ −0.268`，增益 6，沿行、沿列各一遍，`O(WH)`。因果初值按镜像边界把无穷和截断到 `|z₁|ᵏ < 1e-16`（约 27 项）。
- **边界**：whole-sample 镜像（`reflect101`），索引折叠而不是复制数据。
- **性质检查**：预滤波 + 求值在整数坐标上**严格还原原始像素**（实测 `< 1e-9`），在远离边界处**精确重建三次以下多项式**（实测 `< 1e-8`）——两条都写成了测试。
- **求值**：可分离，先沿 y 归约 4 项、再沿 x 归约 4 项，共 16 次乘加。
- 目前**未实现**规格 §2.10 的系数 LUT（1 MP 图约 64 MB），也未实现五次 B 样条。参考实现优先可读性，见 §6。

### 2.4 参考图梯度：4 阶中心差分

```
f_x(i,j) = [ f(i−2,j) − 8f(i−1,j) + 8f(i+1,j) − f(i+2,j) ] / 12
```

内部用 4 阶，倒数第二圈降到 2 阶中心差分，最外圈用单侧差分。

**刻意不用 B 样条的解析导数**：规格 §2.10 要点 4 明确要求梯度与插值器分开，混用会破坏 IC-GN 的一致性论证。代码里对这一条写了注释，测试里对三次多项式验证了 4 阶差分的精确性。

### 2.5 整数初值：FFT 加速 ZNCC 搜索

`integer_search_fftcc()` 按规格 §2.4 实现：

```
1. 参考子区零均值化 F₀ = f − f_m，Δf = ‖F₀‖
2. 目标搜索窗 G（边长 m = (2r+1) + 2s），零填充频域互相关
   R = IRFFT2( conj(RFFT2(F₀, m)) ⊙ RFFT2(G) )[0:2s+1, 0:2s+1]
   —— 因 Σ F₀ = 0，用零均值 F₀ 对原始 G 相关即等于对零均值 G 相关
3. 用积分图（summed-area table）O(1) 求每个候选位置的局部 ΔG
4. ZNCC_map = R / (Δf · ΔG)，取峰
```

复杂度 `O(m² log m)` 而非暴力的 `O(m²N)`。`search_radius = 0`（默认）时完全跳过，退化为零初值——对亚像素平移这类小位移工况是最快路径。

### 2.6 不确定度（UQ）

按规格 §2.6 与 §6.2，`compute_covariance = True` 时输出

```
Cov(p) ≈ 2 σ_n² · H_raw⁻¹ ,   H_raw = Σ_i J_iᵀ J_i
```

对纯位移分量退化为经典的 `σ_u ≈ √2 σ_n / sqrt(Σ f_x²)`。因为 `H_raw` 本来就要算，这个输出的边际成本只有一次 6×6 求逆。**这条是 HL3 相对闭源软件最硬的差异化（R1-O1 §6.2），所以在最小内核里就先占位，而不是留到后面**。

### 2.7 状态码

`Status` 枚举与规格 §2.6 的失败表对齐：`UNCOMPUTED / CONVERGED / LOW_ZNCC / NOT_CONVERGED / OUT_OF_BOUNDS / SINGULAR_HESSIAN / DIVERGED`。`ICGNResult.masked("u")` 把非收敛点置 `NaN`——规格 §2.11 反复强调的"不外推、不零填充"。

## 3. 测试

### 3.1 合成散斑：为什么可信

测试哲学照抄 R1-O1 §5.0：**生成器与求解器不能共用同一个插值器，否则测的是自洽性而不是正确性**。

`tests/test_icgn_synth.py` 内置的生成器与 `.agent_workspace/round1/scripts/synth_speckle.py` 同法：

```
随机脉冲（双线性散射到 8× 过采样画布）
  → 频域高斯卷积（连续纹理）
  → 频域相移 exp(−2πi(u ξ + v η))   ← 对带限图像解析精确
  → 8×8 块平均（模拟像素面积积分）
  → 0.5/99.5 百分位归一化到 0–255，白底黑斑
```

傅里叶相移对带限纹理是**解析精确**的，不引入任何插值误差；求解器用的是双三次 B 样条。两条路径完全不同，因此测出来的偏差是真实的插值偏差 + 求解器偏差，不是自我印证。

另有一个测试（`test_matches_round1_generator`）直接 `importlib` 加载 R1-G2 的 `synth_speckle.py` **原封不动**跑一遍，作为交叉校验；脚本不存在时自动 skip。

| 1.0 | 1.551e−03 | 1.729e−03 | 1.867e−03 | +7.692e−04 | 100.0% |
| 2.0 | 2.838e−03 | 3.194e−03 | 3.517e−03 | +1.109e−03 | 100.0% |
| 5.0 | 6.899e−03 | 7.869e−03 | 8.712e−03 | +2.086e−03 | 100.0% |

σ(u) 与 σ_n 的关系接近线性（σ_n 从 1 → 5 时 σ(u) 从 1.73e−3 → 7.87e−3，比值 4.55 对 5.0），符合 `σ_u ∝ σ_n` 的理论预期；截距由插值偏差与散斑量化决定。**这张表就是 §2.6 协方差公式的定量校核基础**，但严格的 T6 蒙特卡洛验证（100 次独立实现 × 比值落在 [0.8, 1.25]）还没做，见 §6。

### 4.3 subset 尺寸扫描（`u=0.37, v=−0.42`，step 12，无噪声）

| 11×11 | 1.260e−03 | +1.966e−04 | −5.118e−04 | 7.62 |
| 15×15 | 8.939e−04 | +4.981e−04 | −1.746e−04 | 5.13 |
| 21×21 | 7.909e−04 | +4.554e−04 | −2.531e−04 | 4.19 |
| 31×31 | 7.010e−04 | +3.965e−04 | −2.040e−04 | 4.00 |
| 41×41 | 5.874e−04 | +2.898e−04 | −9.236e−05 | 4.00 |

无噪声下 subset 增大主要是**降随机误差**（偏差本身由插值决定，改善有限），同时迭代数从 7.6 降到 4.0。这与 iDICs GPG Recommendation 5.2 把 21×21 定为实用最小值的取向一致：11×11 已经明显更差且更慢。

### 4.4 大位移 + FFT-CC 初值

`u = +7.35 px`、`v = −5.60 px`，192×192，subset 21，step 16，`search_radius = 12`，25 个 POI，全部收敛：

| 指标 | 实测 |
|---|---|
| 平均 \|误差\| | 8.686 × 10⁻⁴ px |
| 最大 \|误差\| | 5.260 × 10⁻³ px |
| bias(u) / bias(v) | +4.687 × 10⁻⁴ / +4.425 × 10⁻⁴ px |

**结论：整数初值链一旦到位，亚像素精度与小位移工况没有区别**（8.69e−4 vs 8.08e−4）——收敛半径问题和精度问题是解耦的，符合 IC-GN 的理论预期。

### 4.5 吞吐（诚实版）

基线工况：196 POI / 0.24 s = **约 815 POI/s，单核，纯 NumPy**。

这个数字**不能**与 ROUND1_BRIEF §3 里讨论的 10⁶ 量级口号相提并论，原因写清楚：(a) 单线程；(b) 每个 POI 一次 Python 循环迭代，subset 内才向量化；(c) 无 GPU；(d) 这是**参考实现**，设计目标是可读、可审计、可作为其他后端的正确性基准，不是性能实现。按 ROUND1_BRIEF §3 的口径，**本环境（4 vCPU 无 GPU）不具备验证 VIC 级吞吐的条件，任何吞吐对比都必须走 R1-G2 的公平协议**。这里给出 815 POI/s 只是为了让 Round 3 知道参考实现的量级基线。

## 6. 已知缺口（交给 Round 3）

1. **T6 蒙特卡洛未做**：§4.2 只给了单次实现的散布，没有做"每个 σ_n 跑 100 次独立噪声种子、断言实测 σ_u 与理论 `√2σ_n/sqrt(Σf_x²)` 的比值落在 [0.8, 1.25]"。协方差输出目前只验证了"有限且量级合理"，**还不能宣称 UQ 已被校核**——而 UQ 是 R1-O1 §6.2 认定的最硬护城河，Round 3 必须把这条补上，否则宣传口径超前于证据。
2. **只测了平移**：旋转（T3）、均匀应变（T4）、应变梯度/空间分辨率传递函数（T5）都没测。一阶形函数的 `u_x…v_y` 分量目前只有"纯平移下应为 0"的弱验证。需要 R1-O1 §5.0 的第二条生成路径（解析散斑函数在变形坐标上直接求值）才能干净地测这些。
3. **插值对照缺列**：`KEYS_BICUBIC` / `QUINTIC_BSPLINE` / `BILINEAR` 未实现，§5.1 的四行对照表只填得出一行。
4. **性能**：815 POI/s 的参考实现无法支撑大图。Round 3 若要跑 DIC Challenge 级数据，需要先做 POI 批量向量化（把逐 POI 的 Python 循环改成对 POI 维度的批处理）。
5. **并行协作**：见 §1 的事故记录，建议 Round 3 强制 per-agent worktree。
