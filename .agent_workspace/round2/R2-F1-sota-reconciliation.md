## 1. 逐条裁决与理由

### RUL-01 许可证：独立重实现 + Apache-2.0 内核 + open-core（接受）

**裁决**：HL3 采用 open-core。`hl3-core`（相关器、标定、应变、UQ、IO、CLI、Python 绑定、原创测试）以 **Apache-2.0** 开源；schema 规范文档独立以 **CC-BY-4.0**；商业 GUI / 采集 / 实时 / 许可管理层为专有商业许可（`LicenseRef-HL3-Commercial`）。全部数值内核（含未来 GPU）**从公开论文独立实现**。并行产出的 `R2-G1-license-adr.md`（ADR-LIC-001）与本裁决一致，**本文予以追认并升格为约束性 ADR**。

**驳回项**：
1. 驳回"内核用 MPL-2.0"（R1-O3 开放问题 1 的候选之一）。MPL 文件级 copyleft 会把"哪些文件被覆盖"的审计负担带进每次发版，与 open-core 的干净 IP 链条冲突；Apache-2.0 的显式专利授权条款对计量软件的商业采用更有利。
2. 驳回任何形式的 OpenCorr 文件级复用（复制、改写、翻译、vendor、链接依赖），不因 MPL 理论上允许 Larger Work 而放宽——按 ADR-LIC-001 §2 执行"只读论文、独立实现、引用 DOI"。
3. 永久禁用 OpenCorr GPU 闭源二进制（`.lib/.dll`）与其 shareware GUI（R1-G1 结论，ADR-LIC-001 §3）。
4. 无许可证仓库（U-DICNet、Stereo-DICNet2 等）只引用论文；"仅研究/非商业"许可（py2DIC）不进入商业 HL3。

**理由**：R1-F1（Apache/BSD open-core）、R1-F3（楔子 #5"开源内核是 VIC 商业模式无法跟进的信任资产"）、R1-G1（"独立实现 + 宽松许可参照"）三方向一致；R1-O3 的 MPL 顾虑本质是"若复用 OpenCorr 则须 MPL"——裁决直接取消复用前提，顾虑随之消失。BSD/MIT 参照仓库（Ncorr C++、pyALDIC、muDIC、DICe 自有代码）仅作 oracle 与测试思想参考，复用时保留通知，且不得把它们写成内核的多重许可。

### RUL-02 CPU 参考实现是计量规范；GPU 是可选后端（接受）

**裁决**：
1. **CPU float64 实现是 HL3 的规范（normative）实现**：一切精度 Gate、golden 文件、Challenge 回归、UQ 验证均以 CPU 实现定义正确性。
2. GPU（CUDA 主后端，可移植层为后续候选）是**可选加速后端**，任何 GPU 路径合入前必须存在同语义 CPU 参考及 parity 测试床。
3. 本云环境（4 vCPU、无 GPU、无 CUDA，R1-G3 实测）的 CI **只跑 CPU**；GPU 基准属于后续外部固定 runner（G2 §10.2），不阻塞 Round 2/3 验收。
4. R1-F1 §3.2"内核从第一天就 GPU-first，CPU 是回退路径"的**表述被推翻**：GPU 是吞吐与实时楔子（F3 楔子 #4），不是正确性锚点。产品叙事保留"GPU 代际差"，工程次序执行"先 CPU 正确，后 GPU 快"（与 R1-F4 铁律 4 一致）。

**理由**：计量软件的可信度来自可审计的规范实现；本环境事实（无 GPU）使任何 GPU-first 的工程排序在三轮内不可验证；路径无关 ICGN 的算法设计已保证日后 GPU 化不需要改架构。

### RUL-03 吞吐：G2 协议是唯一口径，目标表冻结（接受）

**裁决**：
1. **R1-G2 §7（计时边界、公平性、发布包）是 HL3 唯一合法的吞吐测量与发布协议**。任何吞吐数字必须声明：图像尺寸、subset、step、形函数阶、插值、初值策略、收敛/失败判据、计时边界（kernel-resident / warm / cold / sequence 四档之一）、硬件与驱动清单、重复次数与分位数，并附 `benchmark-manifest.json` 与一键复跑命令。
2. Round 1 出现的所有数字（F1 的 GPU ≥5×10⁶ POI/s、O2 的 GPU ≥3×10⁶ 3D-POI/s、F4 的 GPU >1×10⁶、F2 GP-3）一律降格为**协议绑定目标（target）**，不是已达成宣称（claim）。冻结后的单一目标表：

| 档位 | 条件（按 G2 §7 报告） | 目标 | 性质 |
|------|----------------------|------|------|
| 2D · 32 核 CPU | ICGN1，subset 21–31，warm end-to-end | ≥1×10⁶ POI/s | v1 Gate（GP-3） |
| 2D · 单消费级 GPU | ICGN1，subset 21–31，kernel-resident 与 warm 双报 | ≥5×10⁶ POI/s | SOTA Gate（GP-3） |
| 3D · 单消费级 GPU | ICGN1，subset 21，"3D 点"定义见下 | ≥3×10⁶ 3D-POI/s | SOTA 目标（O2 §11.2） |
| 3D · 单消费级 GPU | ICGN2，subset 31 | ≥1×10⁶ 3D-POI/s | SOTA 目标（O2 §11.2） |

3. **"3D 点"的定义冻结**（采 G2 §7.1 + O2 §11.2）：一个 3D POI/s 计入左相机时序匹配 + 右相机匹配（立体匹配按参考帧摊薄）+ 三角化；2D 与 3D 数字永不混用、不共用无说明的 points/s。
4. **禁止**："比 VIC 快 X 倍"、"超过 VIC"等表述在满足 G2 §7.3 全部四条件（同机合法双跑、同配置、同精度门槛、全量披露）之前一律禁止；VIC 的"32 核 CPU 1,000,000 点/秒"只能作为图上一条标注"厂商公开上限；非同机、非同配置、不可直接排序"的参考线。
5. 产品叙事冻结为 O2 §11.2 的表述："**我们不是说更快，是把条件说清楚了**"——可复现的诚实数字优于更大的营销数字。

**理由**：三份文件的数字并不真冲突（分别指 2D GPU、3D GPU、v1 底线），冲突的是"无协议引用"；统一到协议后各数字各归其位。

### RUL-04 显微镜畸变：FTO 书面结论前零实现（接受，维持严格线）

**裁决**：
1. 即使 US7133570B1（Schreier/Sutton，Correlated Solutions）在 Google Patents 显示 "Expired - Fee-Related"（调整后到期日约 2025-05-11，R1-O2 §10.4 检索），**在具资质专利律师出具书面 FTO 意见之前，显微镜/SEM 畸变校正保持零实现**：不写实现代码、原型、伪代码、测试向量、插件接口填充或产品宣传。数据库状态是线索，不是法律结论；同族（EP/JP/CN/KR）、延续案与恢复可能均未清查。
2. 工程侧本轮唯一交付物是**法务检索清单**——已由 R2-G1 §5 完成（种子专利族谱、检索式、法域清单、出口条件），本文追认。
3. **不受限项**：参数化标准畸变模型 L1–L5（Brown–Conrady、鱼眼、远心等，属通用摄影测量公开方法）正常开发；O3 数据模型中 `DistortionModel::StereoMicroscope` 枚举值可以**存在但无任何实现绑定**（保留 schema 槽位不等于实现）。
4. 不得把专利说明书文字、图纸或权利要求措辞复制进任何文档或注释（版权与专利独立）。
5. FTO 放行后走 clean-room：基于独立公开文献链实现，保留设计文档、引用清单与 commit 历史。

**理由**：O2 与 F4 的分歧是"过期迹象是否足以开工"；答案是否——FTO 是法域敏感、族谱敏感的法律判断，工程侧提前开工的收益（一个 P8 可选模块）远小于风险。主线产品（P1–P7）不依赖该模块，冻结无进度代价。

### RUL-05 全局 DIC / AL-DIC：接口进核心随 v1 冻结，实现分期（裁决）

**裁决**：
1. **数据模型与 API 层面：一等公民，随 v1 冻结。** `RunConfig.mode : LOCAL | GLOBAL_FE | ALDIC`（O1 §2.13）、`GridKind::FeMesh`、统一 HDF5 结果 schema（三种模式写同一 schema、可逐点对比）现在冻结进核心接口，Round 2 的 schema 与 `src/` 骨架必须预留这些槽位。
2. **求解器实现层面：分期。** v1 主线只交付 `LOCAL`（路径无关/HYBRID ICGN），它是计量基准与全部精度 Gate 的对象；`GLOBAL_FE`（Q4/Q8 有限元全局 DIC + Tikhonov/力学正则）作为 **v1.x 官方 beta 模块**；`ALDIC`（ADMM 增广拉格朗日混合）作为 **v2 官方模块**。
3. **归属：两者都是官方内核模块（同仓、Apache-2.0），不是第三方插件。** 插件 ABI 照常存在，但 FEA 原生闭环是 F3 楔子 #6 与 GPG Ed.2 Global DIC 附录对应的核心卖点（SOTA Gate GP-4"导入网格上直接全局求解"），不能外包出去导致质量与许可失控。
4. Round 2/3 **不实现**全局求解器，只交付：接口冻结、schema 槽位、`GLOBAL_FE` 的最小接口一致性测试（构造→报错"未实现"或 stub 拒绝，防止接口腐烂）。

**理由**：muDIC/ALDIC/EikoTwin 路线证明市场价值，但 v1 的计量信誉必须由单一、可深度验证的 LOCAL 内核建立；接口先冻结消除 R1-F4 风险 R-09（schema 早期不稳定拖累全部消费方）；分期避免 v1 范围爆炸。

### RUL-06 VIC UI 未知项：强制置信度标签（裁决）

**裁决**：R1-F1 §7 的十项"没有合法 Windows 评估版就无法知道的事"全部维持"**公开信息推断 + 置信度**"条目形态；iris/vicpyx/许可管理/报告模板等 UX 细节**永不进入**任何"已对齐 VIC"清单；R2-F3 的 PRD 与 R2-F4 的验收包不得让任何设计决策依赖这些未知项（它们只影响 GUI 打磨优先级，不影响架构——F1 原判维持）。若用户将来在其自有合法许可的 Windows 工作站完成走查（按 R1-G3 §6 清单），对应条目转为实测并注明日期与版本。本环境内不做、也不尝试任何形式的 VIC 安装或评估流程。

### RUL-07 Round 2 代码落地令（裁决）

**裁决**：Round 2 必须交付可测的 **CPU 一阶 2D ICGN 最小内核**（ZNSSD + 双三次 B 样条插值 + FFT-CC 或平移初值 + 路径无关），并对 `round1/scripts/synth_speckle.py` 产出的合成平移做可重复测试。验收口径直接采 G2 §2.3 初始门槛（无噪声平移 |bias| ≤ 0.01 px、std ≤ 0.01 px、有效点率 ≥ 99.9%；S 曲线峰峰值 ≤ 0.02 px）；本轮"先跑通再收紧"，未达标项以 `xfail` 登记数值差距，**禁止放宽门槛掩盖差距**。实现归 R2-O1 所有（本文不越界写其 `src/`）。

### RUL-08 文档效力顺序与三处口径分歧（新增裁决）

**效力顺序（冲突时从高到低）**：
`LEGAL.md` → 本文件（R2-F1 裁决）+ ADR-LIC-001（R2-G1） → R1-F2 验收 Gate 表 → R1-G2 基准协议 → R1-O1/O2/O3 规格 → 其余 R1 文件。

复审中发现的三处 Round 1 内部口径分歧，一并冻结：

1. **GPU/CPU parity 容差**（O1 §5.15 说 <1e-4 px；O3 说计量模式 <1e-6 px）：**双档并存**——通用 GPU 后端合入门 = 位移差 ≤1e-4 px 且收敛状态一致；`--metrology-mode` 认证门 = ≤1e-6 px 且插件/后端声明 cross-backend 确定性（O3 语义）。两档都进 CI 规格。
2. **空间分辨率截止口径**（F2 锚点 A4 用 20% 衰减；G2 §5.2 主报 L10%、兼容报 L20%）：**双口径并报，禁止混报**；与任何已发表榜单对比时，一律采用该榜单论文的官方口径；HL3 内部回归门禁以 L10% 为主口径。
3. **"点/秒"的定义**：见 RUL-03 第 3 条，2D 点与 3D 点永久分账。

## 2. "超越 VIC-2D 8 / VIC-3D 11" 定义冻结（公开 KPI 清单）

**判定公式（冻结）**：

> **超越成立 ⇔ A 组（精度平权）全部 PASS ＋ B 组（显著优势）≥ 4/6 PASS ＋ C 组（独有能力）全部 PASS**，且每项 PASS 均有第三方可复算的证据包（公开数据集或开源生成器 + `metrics.json` + `benchmark-manifest.json` + 一键复跑命令，见 R1-F2 §5 评审清单）。
