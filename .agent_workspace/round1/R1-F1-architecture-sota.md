## 1. 产品愿景：HL3-2D 对标 VIC-2D 8，HL3-3D 对标 VIC-3D 11

### 1.1 一句话定位

- **HL3-2D**：单相机平面 DIC 全链路工作站。对标 VIC-2D 8 的"平面全场位移/应变 + 实时 + Python 扩展 + 显微/SEM"，以**跨平台、开放不确定度（UQ）、原生 Python、FE 网格原生输出**四点实现超越。
- **HL3-3D**：双目至多目立体 DIC 测量平台。对标 VIC-3D 11 的"立体标定 + 三维形貌/位移/应变 + iris 可视化 + FEA 对比 + 1,000,000 点/秒吞吐"，以**GPU 原生相关器、开放标定与 UQ 溯源、FE-DIC 混合内核、多机头无上限拼接架构**实现超越。

### 1.2 全测量链对照（这是竞争的真正战场）

VIC 的强大不在单个相关器，而在于覆盖"从相机到报告"的完整闭环。HL3 必须逐环节给出等价物 + 超越点：

| 测量链环节 | VIC 现状（公开） | HL3 目标 |
|---|---|---|
| **采集** | VIC-Snap：相机集成、标定辅助、模拟量同步 | HL3-Capture：GenICam/GigE Vision/USB3 Vision 标准优先 + 厂商 SDK 适配层；Linux/Windows/macOS 全平台；PTP/硬件触发同步；采集即写入开放格式（HDF5/Zarr） |
| **标定** | 官方标定板 + 向导；立体标定；显微镜专利畸变校正 | 张正友 + 光束法平差（bundle adjustment）；标定残差全量留存并进入 UQ 传播链；支持第三方与自打印标定板（带不确定度标注）；非参数畸变场补充模型规避专利叙事、走已发表文献路线 |
| **散斑** | 散斑套件 + 打印服务（硬件生意） | 内置散斑设计器：按视场/像素密度自动生成最优图案（打印 PDF/喷涂模板/激光刻蚀 SVG），并内置 MIG、Shannon 熵、自相关半径等质量评估（对齐 iDICs GPG） |
| **相关** | 局部 subset、闭源、1/100 px 宣传、32 核 1e6 点/秒 | ICGN 一阶/二阶 + 路径无关并行 + GPU 原生；局部/全局/混合三内核可切换；开源可审计 |
| **应变** | PLS 平滑窗、VSG、多种应变张量、自定义变量 | 同等张量族（工程/Green-Lagrange/Euler-Almansi/主应变/最大剪切）+ VSG 尺寸显式报告 + 每点应变噪声估计；Q4/Q8 FE 网格直接输出应变场 |
| **可视化** | iris：FEA 导入、等值线、运动模糊动画、4K/PDF 出版图 | HL3-Viz：GPU 渲染（wgpu）、出版级导出、FEA 叠加、**且全部绘图可由 Python API 脚本化复现**（iris 强在交互，弱在可复现） |
| **Python** | vicpyx：v11 才内置，项目内脚本、派生量 | **Python-first**：内核以库形式存在，GUI 只是内核之上的一个客户端；任何 GUI 操作都有等价 API 调用并可录制为脚本 |
| **报告** | 模板报告、复制粘贴到 Office | 模板报告 + 可执行报告（Jupyter/Quarto）：报告内嵌参数与数据哈希，第三方可一键复算 |
| **实时** | VIC-Gauge 点测量 + 全场实时（许可模块） | 实时虚拟引伸计/应变片 + GPU 全场实时；开放输出总线（EtherCAT/UDP/OPC UA/ROS2）用于闭环试验机控制 |
| **相机/硬件** | 交钥匙捆绑（Blue Hawk/Falcon、5,000,000 fps 高速方案） | 不做自有硬件；发布"认证硬件清单"+ 一键自检协议，兼容用户已有相机，把 VIC 的硬件绑定转化为我们的成本优势 |

### 1.3 愿景不是"功能对齐"而是"范式换代"

VIC 的范式是 2000 年代的封闭桌面计量软件；HL3 的范式是**开放计量平台**：内核开源可审计（计量溯源到源码）、数据格式开放（HDF5/Zarr + 公开 schema）、算法可插拔（插件市场）、结果可复现（参数+数据哈希全记录）。这是 GOM/MatchID/EikoSim 都只做了一部分、而 VIC 因商业模式无法跟进的方向。

## 2. 系统架构

### 2.1 分层总览

```
┌─────────────────────────────────────────────────────────────┐
│  应用层    HL3-2D GUI   HL3-3D GUI   HL3-RT(实时)   CLI/批处理 │
├─────────────────────────────────────────────────────────────┤
│  服务层    hl3.project 工程模型 / hl3.report / hl3.viz(渲染)   │
├─────────────────────────────────────────────────────────────┤
│  Python 层  hl3 包（pybind11 绑定 + 纯 Py 工具）＝一等公民 API   │
├─────────────────────────────────────────────────────────────┤
│  内核层    hl3-core (C++20)：correlate / calib / strain / uq  │
│            CPU(OpenMP+SIMD) 与 GPU(CUDA 主 + Vulkan 备) 双后端 │
├─────────────────────────────────────────────────────────────┤
│  采集层    hl3-capture：GenICam/Harvester + 厂商 SDK 插件      │
├─────────────────────────────────────────────────────────────┤
│  数据层    HDF5/Zarr 工程容器 + 公开 schema + 导出器(VTK/CSV…) │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键架构决策（ADR 摘要）

1. **共享内核，两个产品皮肤**。HL3-2D 与 HL3-3D 共用 `hl3-core` 的相关器、应变、UQ、数据模型；3D 额外启用标定、极线匹配、三角化模块。避免 VIC-2D/VIC-3D 双代码库式的功能漂移（公开发布说明显示两者功能上线节奏不同步，如 v8/v11 各自引入 Python）。
2. **Python-first，不是 bolt-on**。vicpyx 是"在 GUI 里跑脚本"；HL3 反过来：内核先以 `pip install hl3` 的库存在，GUI 是消费该库的客户端之一。收益：CI 可测、无头服务器可跑、教学可用 notebook、第三方可集成。这是结构性差异，VIC 无法在不重写架构的情况下模仿。
3. **采集层独立进程**（对标 VIC-Snap）：`hl3-capture` 以独立守护进程 + IPC（共享内存环形缓冲 + Arrow Flight/gRPC 控制面）运行，崩溃不影响分析端；同一采集流可同时喂 GUI 预览、实时相关器与磁盘写入。相机接入优先走 GenICam GenTL（Harvester），厂商私有 SDK（Photron/Phantom 高速机等）做成插件。
4. **实时子系统**（对标 VIC-Gauge + 全场实时）：`HL3-RT` 复用 GPU 相关器，两档模式——(a) 虚拟应变片/引伸计点集模式，延迟目标 < 10 ms，输出到模拟量/EtherCAT/OPC UA 供试验机闭环；(b) 全场降采样实时模式，GPU 上以固定 POI 网格增量更新。实时与离线共用同一相关器代码路径，保证"实时看到的 = 事后算出的"。
5. **可视化引擎**（对标 iris）：`hl3-viz` 基于 wgpu（Vulkan/Metal/DX12 之上的可移植层），场景图支持：网格/点云/等值线/矢量场/FEA 叠加/散斑贴图/时间轴动画；导出 PDF（矢量）、PNG/EXR、H.264/AV1 视频到 4K。所有场景由声明式 JSON/Python 对象描述——iris 的动画要在 GUI 里逐帧调，HL3 的动画是一段可版本控制的脚本。
6. **工程容器开放**：`.hl3proj` 即 HDF5（或大数据场景 Zarr）目录，schema 公开发布并语义化版本管理。任何人不装 HL3 也能用 h5py 读全部结果——与 VIC 专有工程文件形成信任层面的对照。
7. **插件体系**：相关器、形函数、应变滤波器、导出器、相机驱动、可视化图层六类扩展点，Python 或 C ABI 插件均可。目标是复制"VS Code 生态打败封闭 IDE"的路径。

### 2.3 部署形态

单机桌面（三平台）、无头 CLI/集群批处理（SLURM 友好，路径无关算法天然可分布）、以及"采集站 + 算力站"分离部署（高速试验现场常见）。许可模型：内核 Apache-2.0/BSD 开源 + 专业版闭源增值（实时模块、专业支持、认证硬件包）——"open-core"直接攻击 VIC 的许可摩擦。

## 3. SOTA 算法栈：如何在算法上压过局部 subset DIC

VIC 公开叙事以经典局部 subset + 高度优化 CPU 实现为核心。HL3 的算法栈按"金字塔"组织，每层都有已发表文献与开源参照，不依赖任何 VIC 内部细节：

### 3.1 初值层（integer-pixel / 种子）

- FFT-CC 粗搜索（OpenCorr 同款路线）；
- SIFT/特征仿射初值（大变形、旋转、断裂前后帧）——Yang 2020 OLE 的 SIFT-aided 路径无关方案；
- DL 初值（见 3.6）作为第三选项，处理散斑退化/遮挡。

### 3.2 亚像素精配层

- **ICGN 一阶 + 二阶形函数**为主力（逆合成高斯-牛顿，Hessian 预计算，收敛快且精度业界公认）；辅以 IC-LM（逆合成 Levenberg-Marquardt，OpenCorr 2024.12 新增路线）增强病态子区的鲁棒性。
- **路径无关**（Jiang 2015：每 POI 独立初值+ICGN）取代可靠性引导路径的串行依赖 → 天然全并行，无误差沿路径累积，断裂/不连续场景不"断链"。
- **GPU 原生**：ICGN 每 POI 独立、计算密集、分支少，是完美的 GPU 负载。已发表工作（Zhang 2015 OLE 的 GPU-ICGN、OpenCorr ICGNGPU）证明消费级 GPU 上 >10⁵–10⁶ POI/s 量级可达。HL3 内核从第一天就 GPU-first，CPU 是回退路径——与 VIC "32 核 CPU 达 1e6 点/秒"的宣传形成代际差：我们的目标是**单张消费级 GPU ≥ 5×10⁶ 点/秒**（一阶 ICGN、31×31 子区，收敛判据与公开 Challenge 一致时报告）。
- 亚像素插值：双三次 B 样条预滤波（计量级标准做法），灰度归一化 ZNSSD 准则抗光照。

### 3.3 全局/混合层（VIC 没有的公开能力）

- **FE 全局 DIC**（muDIC、2D_FE_Global_DIC 路线）：位移场在 Q4/Q8 网格上直接求解 + Tikhonov/平衡间隙正则，输出天然是 FE 网格 → FEA 验证不再需要"点云→插值→网格"的后处理（EikoSim 以此差异化，HL3 把它做进内核）。
- **AL-DIC 混合**（Yang & Bhattacharya 的增广拉格朗日方案，pyALDIC 参照）：局部子区速度 + 全局运动学协调，ADMM 迭代。作为默认高精度模式：先路径无关局部 GPU 扫描，后 AL 全局一致化。
- 自适应子区/网格：按散斑质量图与应变梯度局部加密（OpenCorr 已有 self-adaptive subset 示例，学术界成熟）。

### 3.4 立体与多相机层

- 张正友标定 + 全参数光束法平差；标定不确定度协方差全程留存。
- 立体匹配：极线约束 + SIFT 引导 + 二阶 ICGN（Stereo-DIC Challenge 样本验证路线）；三角化后在切平面上算应变（Green-Lagrange，曲面局部坐标系）。
- **多相机图（camera graph）架构**：不设"主从对"硬编码，N 相机组成观测图，全局光束法平差解系统外参 → 多系统拼接从"16 相机上限"的产品参数变成"图规模"的工程参数。DuoDIC/MultiDIC 提供学术参照。
- 离面/2D 伪应变自检：HL3-2D 内置离面运动误差估计器（2D DIC 最大误差源，iDICs GPG 重点），这是 VIC-2D 公开材料不强调的诚实性功能。

### 3.5 不确定度量化（UQ）——HL3 的旗舰差异化

MatchID 证明了"UQ 叙事"在市场上有效；HL3 把它做成默认输出而非选配：

1. 相关阶段：每 POI 的 ZNSSD 残差 → 位移协方差（Cramér-Rao 下界估计）；
2. 标定阶段：标定参数协方差 → Monte Carlo/一阶传播到三维坐标；
3. 应变阶段：VSG 窗口效应显式建模，报告"应变空间分辨率 vs 噪声"曲线（即 DIC Challenge 2.0 的 MEI 框架）；
4. 每个导出的云图都可叠加"置信度图层"；报告自动包含 iDICs GPG 要求的全部元数据表。

### 3.6 深度学习：助攻位，不是主力

明确立场：DL 网络（Stereo-DICNet、U_DICNet、ECI-Net 等）用于——初值预测、大变形/遮挡桥接、散斑质量评估、坏点修复;计量主链仍是 ICGN/FE-DIC。任何 DL 组件要进入默认管线，必须先在 DIC Challenge 2.0 图集上以 MEI 指标击败传统管线并给出失效模式分析。这条纪律既是科学诚实，也是对抗"黑箱 AI 不可信"质疑的卖点。

## 4. 为什么 VIC 难打，以及每一条的精确攻击向量

| # | VIC 护城河 | 强度 | HL3 攻击向量 |
|---|---|---|---|
| 1 | **硬件锁定**：交钥匙系统（相机/镜头/标定板/散斑套件/Blue Hawk） | 高 | 不硬碰：发布开放"认证硬件矩阵"+自动自检协议，让用户用现有相机达到已知精度等级；把 VIC 的捆绑价转化为 HL3 的 10 倍成本优势 |
| 2 | **品牌与创始人权威**（Sutton 系、25 年、iDICs 话语权） | 高 | 用**公开可复现的 Challenge 成绩**说话：每个版本发布都附 DIC Challenge 2.0 / Stereo Challenge 全套 MEI/噪声底数据与复算脚本；邀请第三方实验室复测 |
| 3 | **工业支持/培训/认证** | 高 | 开源社区 + 商业支持双轨；文档/教程/notebook 全公开；和高校实验课合作（对标 VIC-EDU 的位置但免费） |
| 4 | **Windows 桌面 UX 成熟度**（模板、报告、复制粘贴、暗色主题这类打磨） | 中 | 承认短期打不过其打磨度；用跨平台（Linux 集群 + macOS 笔记本 + Windows）与"GUI 操作=可录制脚本"换道超车 |
| 5 | **1e6 点/秒吞吐宣传** | 中 | GPU 代际差正面击穿：公开基准（固定图集、固定收敛判据、公布硬件）目标 ≥5e6 点/秒；同时公开我们的测试方法，反衬其宣传数字无复现协议 |
| 6 | **FEA 对比工作流（iris + 对齐工作区 + Levenberg-Marquardt 材料参数估计）** | 高 | FE-DIC 原生内核：位移场直接解在 FE 网格上，不确定度随场输出 → 从"DIC 结果对比 FEA"升级为"DIC 直接在 FEA 网格上测量 + 参数辨识（VFM/FEMU 模块）" |
| 7 | **FFT 振动/ODS 模块** | 中 | 全场 FFT/FRF + UNV 导出为 P1 路线图项；GPU 全场实时使"在线 ODS"成为可能（VIC 为离线处理叙事） |
| 8 | **多相机 16 系统拼接** | 中 | 相机图架构（3.4 节）无硬上限；用 PTP 时间同步 + 全局光束法平差把拼接做成一等公民 |
| 9 | **立体显微镜专利畸变校正叙事** | 中 | 规避专利具体权利要求；走已公开发表的非参数畸变场/自标定文献路线；显微 DIC 列为 P2，先行法律尽调（Round 2 任务） |
| 10 | **许可/销售模式**（PC 绑定密钥、销售跟进） | 反向弱点 | open-core：`pip install hl3` 三分钟出第一张应变云图 vs 官方评估流程按天计；这是 time-to-first-result KPI 的直接来源 |

综合判断：VIC 在**硬件+支持+品牌**上的护城河短期无法正面攻破；HL3 的胜利路径是先拿下"预算有限但技术敏感"的科研/初创/教学市场（VIC 因价格与许可摩擦覆盖薄弱），以公开基准建立算法信誉，再借 FE-DIC + UQ + 跨平台进入工业验证市场。

## 5. 推荐技术栈与模块边界

### 5.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 内核语言 | C++20（概念、ranges、`std::mdspan`） | 计算密集 + 生态成熟；Rust 列为观察项不阻塞主线 |
| GPU | CUDA 主后端；Vulkan compute（或 SYCL）第二后端 | CUDA 生态与 profiling 无可替代；第二后端保 AMD/Apple 与"无厂商锁定"叙事 |
| CPU 并行 | OpenMP + xsimd/highway SIMD | 路径无关算法天然数据并行 |
| 绑定 | pybind11（评估 nanobind） | Python-first 的地基 |
| Python 栈 | NumPy/SciPy/xarray + h5py/zarr | 科学生态无缝 |
| GUI | Qt 6（QML）+ 内嵌 wgpu 视口 | 三平台原生质感；许可走 LGPL 动态链接或商业许可 |
| 可视化 | wgpu 渲染核 + Matplotlib 出版图导出 | 交互性能与出版质量分开优化 |
| 数据 | HDF5（工程容器）/ Zarr（大序列）/ Arrow（IPC） | 开放、可并行读写 |
| 导出 | CSV、VTK/VTU、Exodus、STL/PLY/OBJ、MATLAB .mat、UNV（FFT） | 覆盖 VIC 全部公开导出面 + FE 生态 |
| 相机 | Harvester/GenTL + 厂商插件（Basler/FLIR/Photron/Phantom…） | 标准优先，私有 SDK 隔离在插件内 |
| 标定 | 自研内核（Eigen + Ceres 光束法平差） | 不确定度协方差必须自持，不能依赖 OpenCV 黑箱输出 |
| 测试/CI | 合成散斑生成器 + DIC Challenge 图集回归 + GPU CI 跑分 | 每次提交都有 MEI 回归线 |
| 许可证 | 内核 Apache-2.0；GUI/RT 专业版商业许可 | open-core（参考 DICe BSD、OpenCorr MPL 兼容性，落地前由 R1-G1 复核） |

### 5.2 模块边界（仓库/包划分）

```
hl3-core/        # C++：correlator(局部/全局/AL)、shape-fn、interp、
                 #      calib、triangulate、strain、uq、scheduler
hl3-capture/     # 采集守护进程 + 相机插件 + 同步(PTP/硬件触发) + 模拟量DAQ
hl3-python/      # pip 包：绑定 + 高层 API + 散斑设计器 + 报告生成
hl3-viz/         # wgpu 场景图 + 出版导出 + FEA 网格叠加
hl3-apps/        # HL3-2D GUI、HL3-3D GUI、HL3-RT、CLI
hl3-formats/     # .hl3proj schema、导入(FE: Abaqus/ANSYS/Exodus)、导出器
hl3-bench/       # Challenge 图集适配、合成散斑、MEI/噪声底自动评测
```

边界规则：`core` 不依赖 Qt/相机 SDK；`apps` 不直接调 `core` 的 C++ 而是走 Python 层同一 API（保证 GUI=脚本等价性）；`bench` 是发布门禁而非附属品。

## 6. "超越"的定义：可测 KPI

宣称超越必须落在第三方可复算的指标上。验收协议细节由 R1-G2 展开，此处定义顶层 KPI：

1. **精度（2D）**：DIC Challenge 2.0 全图集，MEI（计量效率指标）进入已发表结果第一梯队；Star 图案位移噪声底 ≤ 0.005 px（一阶 ICGN、标准窗口下）；PIB（图案诱导偏差）报告并低于图集已发表中位数。
2. **精度（3D）**：Stereo-DIC Challenge 1.0 刚体运动集，±20 mm 行程内三维误差 < 80 µm 的已发表包线之内且优于其中位软件；应变噪声底 ≤ 20 µε（VSG 与曝光条件按 iDICs GPG 报告）。
3. **吞吐**：公开基准协议下，GPU 一阶 ICGN ≥ 5×10⁶ POI/s（RTX 级消费卡）、CPU 回退 ≥ 1×10⁶ POI/s（32 核）——即 CPU 就打平 VIC 宣传值，GPU 高一个量级；全部附复算脚本与硬件清单。
4. **实时**：虚拟应变片模式端到端延迟 < 10 ms @ 1 kHz 点更新；全场实时 ≥ 25 fps @ 10⁴ POI（对标 OpenCorr 实时立体演示量级并超出）。
5. **首结果时间（TTFR）**：从"拿到安装包"到"第一张应变云图"< 15 分钟（`pip install hl3` + 示例数据）；对照组：VIC 官方评估流程需 Windows 机器 + 密钥申请表 + 销售响应（以天计）。
6. **平台**：Linux/Windows/macOS 三平台 CI 全绿；无头集群批处理吞吐随节点数线性扩展 ≥ 0.8 效率（路径无关并行红利）。
7. **可复现性**：任意工程文件在异机复算，位移场逐点差 < 1×10⁻⁴ px（确定性模式）；每份报告含数据哈希 + 参数快照。
8. **UQ 覆盖率**：100% 输出量带不确定度通道；标定→位移→应变协方差传播链有合成数据端到端验证。
9. **生态**：公开插件 API 稳定版本发布 + ≥ 3 个第三方插件示例（相机、导出器、滤波器各一）作为生态起搏器。

超越判定 = (1)(2) 精度不输 + (3)(4)(5)(6) 至少四项显著优势 + (7)(8) 独有能力成立。

## 7. 没有合法 Windows 评估版就无法知道的事（诚实清单）

以下只能在用户持有合法许可的 Windows 工作站上走查后补齐（本 Linux 环境不做、也不允许做）：

1. VIC-2D/3D 实际 UI 信息架构：AOI 编辑器交互细节、种子点工作流、错误提示与恢复路径。
2. 工程文件真实内部结构与增量保存行为（我们只需要知道"它是专有的"即可，不逆向）。
3. vicpyx API 的实际表面积、脚本能力边界与性能（公开材料只有营销级描述）。
4. iris 动画编辑器的操作成本与导出质量的真实水平（决定 hl3-viz 打磨优先级）。
5. 实时模块的真实延迟/抖动与试验机闭环接线细节。
6. 1e6 点/秒宣传对应的子区/收敛/图像规格（无公开复现协议，只能自建对照基准）。
7. 标定向导的引导质量、标定失败诊断信息的丰富度。
8. 许可管理器、浮动许可与离线激活的实际体验。
9. 报告模板系统的真实灵活度与 Office 集成细节。
10. 高速相机（Photron/Phantom）在 VIC-Snap 内的集成深度。

处理方式：Round 2 为每项建立"公开信息推断 + 置信度"条目；若用户提供合法许可环境，转为实测条目。所有 HL3 设计决策**不依赖**上述未知项——它们只影响 GUI 打磨优先级，不影响架构。
