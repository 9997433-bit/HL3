## 0. 路线图总原则

1. **阶段门（Phase Gate）而非日程表**。每个阶段以"出口证据（测试证据清单）全部通过"为完成定义（DoD），下一阶段以"入口依赖满足"为启动条件。允许阶段间流水线重叠，但**任何数值内核 API 冻结前，禁止在其上开工 GUI 大规模开发**。
2. **计量优先于功能**。每一项对外宣称的精度指标（亚像素偏差、应变分辨率、吞吐）必须由可重复脚本 + 公开/合成数据集支撑，证据入库（`benchmarks/` + HDF5 结果 + CI 工件），这是对 VIC 闭源黑盒的核心差异化。
3. **单内核双产品**。HL3-2D 与 HL3-3D 共享相关内核、应变引擎、数据模型、可视化与 Python API；3D 仅在标定/立体匹配/三角化/曲面应变上叠加。禁止两套相关器分叉。
4. **CPU 参考实现先行，GPU 追平**。所有 GPU 路径必须存在 float64 CPU 参考实现与逐点数值一致性（parity）测试床，先正确后快。
5. **法律红线贯穿**：只用公开规格 + 文献 + 许可证兼容的开源参考；VIC 的 UI/交互认知只来自公开视频与宣传册（见风险 R-04）。

## P1 — 共享内核（图像 IO · subset ICGN · 应变 · HDF5）

**目标**：建成两款产品共用的计量级 CPU 参考内核，API 冻结，数值证据齐备。

### 工作包

| WBS | 工作包 | 说明 |
|-----|--------|------|
| 1.1 | 图像 IO | 8/10/12/16-bit 灰度、Bayer、TIFF/PNG/BMP、原始帧序列；大序列 mmap/分块流式读取；元数据（时间戳、曝光） |
| 1.2 | 插值与梯度 | 双三次 / 双五次 B 样条插值（亚像素系统偏差控制的关键）；图像梯度预计算；可选低通预滤波 |
| 1.3 | 整像素初值 | FFT-CC 粗搜索 + 金字塔；种子点传播（可靠性引导 RG 与路径无关双策略，接口统一） |
| 1.4 | 亚像素 ICGN | 逆合成高斯-牛顿，一阶/二阶形函数；ZNCC/ZNSSD 准则；收敛准则与迭代上限可配；逐点质量指标（ZNCC 值、残差、协方差估计） |
| 1.5 | 应变引擎 | 位移场 → PLS（逐点最小二乘）平滑窗（可配 VSG 尺寸）→ 工程 / Green-Lagrange / Euler-Almansi / 主应变 / 面内转角；刚体运动去除 |
| 1.6 | HDF5 数据模型 | 版本化 project schema：图像引用、AOI、参数、逐点结果（位移/应变/质量）、标定（预留 3D 槽位）、审计日志；向前兼容策略 |
| 1.7 | pybind11 绑定 | 内核全 API 的 Python 绑定（Python-first，不是事后补丁）；NumPy 零拷贝视图 |
| 1.8 | 合成散斑生成器 | 已知真值位移场（平移/旋转/正弦/高斯斑/大变形）渲染器 —— 是 P1–P7 一切精度证据的地基（与 R1-G2 基准协议对齐） |

### 交付物
- `hl3-core` C++20 库 + Python 包（Linux/Windows/macOS CI 全绿）
- 《内核 API 冻结说明 v1.0》 + HDF5 schema v1
- 《亚像素精度报告 v1》（偏差曲线、噪声底板）

### 依赖
- P0 的技术栈 ADR、许可审计（决定可参考哪些开源实现的思想）。

### 风险
- 插值方案引入系统性亚像素偏差（S 型偏差曲线）→ 双五次样条 + 偏差扫描回归测试锁死。
- HDF5 schema 早期抖动拖累后续阶段 → schema 评审门 + 版本迁移测试。
- 过早优化损害正确性 → 本阶段只做算法级复杂度优化，SIMD/GPU 留给 P4。

### SOTA 门槛（对标公开指标）
- VIC-2D 8 公开宣传运动分辨率 **1/100 像素**。HL3 门槛：合成散斑亚像素平移扫描（0→1 px，步长 0.05）**平均偏差 ≤ 0.01 px，标准差 ≤ 0.01 px**（无噪声）；加噪（信噪比对齐 Challenge 条件）下与已发表 ICGN 文献噪声底板同级或更优。
- 支持二阶形函数（对齐学术 SOTA，处理高梯度变形）。

### 出口测试证据
1. 平移/旋转/正弦变形合成集的偏差-标准差曲线（CI 工件，回归锁定）。
2. 2D-DIC Challenge 样例集（Sample 系列）结果表 vs 文献公开值。
3. 静态图像对噪声底板报告（位移与应变，含 VSG 尺寸扫描）。
4. 单测覆盖率 ≥ 80%（内核数值路径 100% 分支有断言）；三平台 CI 绿。
5. Python 绑定端到端 notebook：读图→相关→应变→HDF5 往返一致性。

- 《CPU/GPU 数值一致性规格与报告》《吞吐基准报告》

### 依赖
- P1 内核数值冻结（parity 的参考基准）；P2/P3 流水线（接入点）；P0 GPU 后端 ADR。

### 风险
- GPU 数值不一致（R-02）：float32 精度、非确定性归约、插值查表误差 → parity 测试床先于优化落地；任何优化 PR 必须附 parity 工件。
- GPU 厂商锁定 → 可移植层保底路径（性能可降级，正确性不降级）。
- 实时路径受 GUI 线程/OS 调度干扰 → 实时管线独立进程 + 延迟直方图纳入 CI 基准。

### SOTA 门槛
- VIC-3D 公开宣传单台 32 核 CPU 达 **1,000,000 点/秒**。HL3 门槛：单张主流工作站 GPU 上稳态 **> 1,000,000 POI/s**（标准 subset 尺寸负载，条件全公开），并给出 CPU-only 回退基准。
- 实时 Gauge：端到端延迟预算达成（数值与延迟同时达标，指标值由 P0 验收表定），长时运行无漂移。

### 出口测试证据
1. Parity 报告：全基准语料逐点差异统计（均值/分位数/最大值）在容差规格内。
2. 吞吐基准表（≥2 档 GPU + CPU 回退），CI 回归锁定。
3. 24 小时实时 Gauge 浸泡测试：无内存增长、无延迟漂移、结果与离线复算一致。
4. GPU 路径跑通 P1/P2/P3 全部黄金集且结果在容差内。
