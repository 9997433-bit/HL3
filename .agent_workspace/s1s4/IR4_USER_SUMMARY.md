# S1–S4 用户总结：HL3 当前能做什么、还不能做什么

> 证据口径：已等待并反复检查 `.agent_workspace/s1s4/` 3 分钟以上，读完汇总前出现的 `IR4_G2_customer_gap.md`、`IR4_O1_web_refresh.md`、`IR4_O2_coverage.md`、`IR4_O3_legal.md` 与 `IR4_F3_actual_gap_matrix.md`，并交叉核对 S1–S4 阶段简报、当前模块清单和 `benchmarks/metrology/metrics.json`。VIC、MatchID、OpenCorr 的能力来自截至 2026-08-28 的公开资料，并未在本环境安装后同机独立验证。

## 1. 本阶段（S1–S4）实际交付了什么

交付物的准确定位是：**一个可审计、CPU/NumPy、Python-first 的 DIC 研发内核，以及离线 2D 的最小无头链；不是 VIC/MatchID 的可替换产品。**

### S1：2D 相关与应变地基

- 独立实现了一阶/二阶 ICGN、ZNSSD/ZNCC 质量量、B 样条亚像素插值、FFT 粗初值和参考更新等计算部件。
- 形成 2D pipeline：灰度图 → POI 位移 → 状态/相关质量 → 应变。
- 实现 PLS 应变估计、VSG 记账，以及工程、Green–Lagrange、Euler–Almansi、Hencky 等应变张量。
- 合成平移已有可复跑数字：一项 196 POI 测试的 MAE 为 `0.0008078 px`、RMSE 为 `0.0010973 px`；相位 S 曲线峰峰偏差为 `0.0017295 px`。这些是**合成数据结果，不是 VIC/OpenCorr 同机成绩，也不是 Challenge 成绩**。
- 阶段简报记录过 `460 passed`，但 S1 正式出口仍因 Challenge 数据和 schema 冻结缺失而未关闭。

### S2：立体匹配与 3D 位移原型

- 实现 `stereo.match`、三角化和 `pipeline.dic3d`，可在调用者提供投影矩阵的前提下输出形貌及 `U/V/W`。
- 有 Sampson/重投影误差、手性检查、四路闭环和逐点拒绝原因等质量诊断。
- 精确针孔合成台架在每相机 `0.02 px` 输入噪声下得到约 `4.90 µm` 3D RMS；该数字明确只代表**已知精确标定、零畸变的闭环几何**，不是端到端 Stereo-DIC。
- 没有真实标定板检测、Zhang 平面标定产品链、束调整、镜头畸变模型、曲面 3D 应变和 Stereo Challenge 成绩。

### S3：UQ、确定性与数据校验

- 实现图像噪声 → 位移协方差 → 应变 CI 的 UQ 传播，并有 Monte Carlo 交叉检查。
- 实现同机确定性、参数快照、`config_hash`/`input_hash`、失败状态和 NaN 保真。
- 提供 HDF5 `.hl3` schema 草案、纯 h5py 读取路径和 `hl3 validate`。
- 阶段简报记录过 `689 passed`；但常用重叠 subset 下，相邻 POI 独立假设导致应变标准差预测仅为实测的 `0.55–0.58`，约低估 `1.8×`；3D UQ 也未计入标定协方差。

### S4：CLI、出图、FEA/GUI 最小表面

- 注册了 `hl3` 命令入口，支持 `doctor|run|validate`；`run` 复用 2D pipeline，并提供合成输入用于 CI。
- 提供无头 `save_field`：内建 PNG/PPM，安装 matplotlib 后可输出 PNG/PDF/SVG。
- 提供内存中 2D 三角网格上的 DIC↔节点投影（barycentric / least-squares / nearest）。
- 提供 `PolygonAOI` JSON 侧车类和 GUI/viewer 包骨架。
- 增加 `viz` 可选依赖和 Linux CPU CI 表面。
- 但 `run` 仍不生成完整 `.hl3`，3D 没有 CLI 端到端入口；FEA 没有 VTK/Exodus/Abaqus/ANSYS 文件链；viewer 明确不启动可用交互会话，AOI 也未接入计算 pipeline。
- 最终工作树快照的独立扫描记录为 `700 passed in 46.09s`。法律/合规实质扫描 PASS：无 VIC 专有资产、无 OpenCorr 代码复用、无逆向、无 GPU/相机 SDK/显微镜实现；但项目自有 L-2 allowlist 流程形式上仍为 FAIL，见第 5 节。
- 覆盖率实测为行覆盖 `88%`、含分支综合 `85%`；但 700 个测试中 633 个集中在 S1–S3 数值内核，S4 的 CLI/viz/FEA/GUI 合计只有 8 项，不能把全局高覆盖率理解为产品表面已充分验证。

### 交付成熟度

- 包版本仍为 `0.0.1.dev0`，分类为 `Pre-Alpha`。
- 核心依赖很轻，仅 NumPy；许可证为 Apache-2.0。
- 按 36 项真实功能复评：`DONE 6`、`PARTIAL 11`、`MISSING 15`、`LEGAL-BLOCKED 1`、`WONT-V1 3`。17 个商业替代底线项中，真正 DONE 的主要只有 2D 相关、无头 CLI 和开源许可形态。
- 当前适合：离线、单相机、灰度图、非安全关键、允许 Python、保留既有生产链的**影子复算**。
- 当前不适合：正式 3D 应变、硬件采集、实时/闭环、认证报告、合同验收、安全决策或替换正在运行的 VIC 工程。

## 2. 算法能否对标 VIC / MatchID / OpenCorr

### 总结

**目前不能证明“算法已对标”，更不能证明“产品已对标”。** 已有结果只能证明若干公开算法在自产合成数据上能工作。

- **对 VIC：不能判定对标。** 没有 VIC 同机同图对照，没有官方 2D/Stereo Challenge 成绩，没有真实镜头畸变、实体标定板、刚体台或拉伸试验。VIC 的公开产品能力覆盖采集、标定、2D/3D 应变、逐点 `Sigma/Sigma_X/Y/Z`、实时、可视化、报告和支持；HL3 只覆盖其中的离线计算内核最小面。
- **对 MatchID：不能判定对标。** MatchID 的公开强项是 Performance Analysis/UQ、标定、FEDEF、FEVAL、VFM 和多相机。HL3 虽有 UQ 数学链和三角网格投影，但 UQ 在常用重叠参数下未通过覆盖口径，且没有标定协方差、同滤波 FE 对照、虚拟试验或材料反演。
- **对 OpenCorr：不能判定对标。** OpenCorr 公开支持 2D、立体 3D、DVC、GPU ICGN、ICLM，并在 2026 年发布 GUI 3.0。HL3 没有对同一数据、相同边界和相同硬件做 OpenCorr 基准；当前还是单线程 NumPy，既无 DVC/GPU，也无同等级 GUI。HL3 的二阶 ICGN、显式 UQ、Python API 和开放 schema 是可比较的设计点，不是胜负证据。
- **2D 核心的证据强度：实验室原型级。** `0.0008078 px` 合成平移 MAE、约 `0.00343/0.00356 px` 的合成静态噪声空间标准差说明实现有潜力；正式 A1 门因 DIC Challenge 数据缺失而不可评估。
- **3D 核心的证据强度：理想几何原型级。** `4.90 µm RMS` 依赖精确针孔真值与已知投影矩阵，不能外推到有畸变的真实相机，更不能外推到曲面应变。
- **性能证据不足。** 小型合成 2D 趋势约 `770 POI-solves/s`，而且是单线程 CPU；没有与 VIC 公开并行吞吐或 OpenCorr GPU 做合法同机比较。
- **正式超越判定为 0。** 既有门禁总结已明确：S4 后 B 组 `0/6` 正式 PASS；A 组 Challenge 证据、B 组产品完备度和 C 组跨机/UQ 证据都没有闭合。
- **功能数量也不支持“已经对标”。** 36 项矩阵只有 6 项 DONE，15 项 MISSING；立体 3D、可视化、开放格式、FEA、VSG、AOI、UQ 等 11 项都只是 PARTIAL。

因此，合规表述只能是：**“HL3 已完成可审计测量链地基，在部分合成测试上表现良好；尚无证据证明精度、鲁棒性、吞吐或产品能力对标 VIC、MatchID 或 OpenCorr。”**

## 3. 哪些方面已经超越或具备超越条件

### 已形成明确优势

1. **源码可审计。** ICGN、状态码、应变张量、VSG、三角化、UQ 和投影均可追到源码与测试；这在透明度上明显区别于 VIC/MatchID 的闭源内核。
2. **Apache-2.0、计算全链无许可证锁。** 可直接检查、修改、容器化和自动部署。VIC 11.4 已有免许可只读 Viewer，ZEISS 也有免费层，因此优势必须限定为“分析、出图、验证均无专有许可”，不能再笼统宣传竞品都存在许可摩擦。相对 OpenCorr，优势不在“开源”本身，而在更宽松许可证和 Python/NumPy 接入；尚未做完整生态对比。
3. **Linux/无头/CI 一等公民。** 数组即 API，已有 CLI、CI 和无头出图表面，适合 notebook、批处理和自动回归。VIC 已发布可 `pip install` 的官方 `vicpyx` 和开放社区扩展索引，所以“有 Python/插件”本身已不是 HL3 独有优势；差异应限定为 Linux 全链、开放内核与无专有容器依赖。
4. **失败更透明。** status、ZNCC、迭代数、Sampson、重投影、手性、位置 sigma 和逐点拒绝原因均可保留；无效点使用 NaN/掩膜，而不是为了填满云图静默插值。
5. **同机确定性和参数溯源。** CPU float64、固定种子、参数快照和输入/配置哈希为可重复回归提供了基础。
6. **应变后处理透明。** 多套有限应变张量和 PLS/VSG 公开实现；改变应变窗口可复用位移结果。
7. **独立实现与法律边界清楚。** 全量扫描未发现专有二进制、OpenCorr 资产、逆向或许可绕过材料；S4 的 viz/FEA/GUI 也没有 UI 仿制或受限色表资产。

### 具备超越条件，但尚未兑现

1. **端到端 UQ。** VIC 已公开逐点匹配与三角化 `Sigma/Sigma_X/Y/Z`，并明确其不包含 bias；HL3 可能形成的差异只能是“图像噪声 → 位移/3D → 应变 CI 的完整传播与覆盖率实证”。如果补齐重叠 POI 空间协方差、标定协方差和实体覆盖率证据，才可能逼近 MatchID 的强项；当前数值仍会过度乐观。
2. **开放数据。** 公开 `.hl3` schema、纯 h5py reader 和 validator 是正确方向；在 `run` 真正写出完整容器、schema 1.0 冻结和互操作转换器完成前，还不是端到端优势。
3. **开放复现实验。** 若将 Challenge 全流程、环境、数据 manifest 和指标一并公开，可形成商业产品与多数开源库都较弱的复现资产；当前 Challenge 成绩为零。
4. **自动化 FE 对照。** 现有双向投影可作为 MatchID FEVAL/levelling 类同滤波比较的起点；“同滤波链”是 MatchID 已公开的方法学，不是 HL3 首创。当前没有真实 FE 文件、配准、同 VSG 滤波和 z 残差闭环。
5. **跨平台。** 纯 Python/NumPy 结构具备三平台可能性；目前只有 Linux CI，不能宣称已跨平台交付。

## 5. 代码审查发现的问题

### P0：会阻断正确测量或造成高风险误用

1. **真实 3D 标定链缺失。** 当前主要依赖外部投影矩阵和无畸变针孔模型；没有标定板检测、完整 Zhang/BA、镜头畸变和标定协方差。真实镜头下的尺寸、形貌、W 和 sigma 均无资格外推。
2. **3D 曲面应变缺失。** `Dic3DRun` 只给形貌与 `U/V/W`，不能交付 VIC-3D/MatchID Stereo 的核心表面应变结果。
3. **UQ 在常用重叠 subset 下系统性偏乐观。** `step≈subset/4` 时预测/实测仅 `0.55–0.58`；若把当前 CI 用作验收置信区间，会低报风险。
4. **没有实拍计量资格证据。** A1/A5/A6 等正式门未闭合，`metrics.json` 仍明确记录 S1/S2/S3 出口为 false/not-evaluated。合成数字不得用于认证、失效或安全决策。
5. **结果容器链未闭合。** `hl3 run` 不写完整 `.hl3`，schema 仍为 `1.0.0-draft.2`；完整图像、标定、UQ、审计和报告不能形成一个可归档交付包。
6. **生产输入链不存在。** 无相机 SDK、触发、同步、掉帧处置和模拟量链；真实试验无法由 HL3 独立可靠采下。
7. **真实图像入口与正式分发物不足。** 16-bit TIFF/PNG/视频/相机序列不是稳定核心入口，也没有 PyPI 与三平台安装产物；正式“安装→首图”门不可评估。
8. **有效性阈值族不完整。** 缺一致性/预测裕度、投影误差、置信区间、立体裕度和可匹配性等成组语义，导致输出留洞规则无法与商业/开源基线公平比较。
9. **真实读图链实际零测试执行。** `load_image` 及 `.npy/.npz/Netpbm/Pillow` 四个后端共约 78 条语句没有任何测试跑到；当前 2D CLI 成功证据只走 `--synthetic`，因此“支持真实文件”尚无回归保障。
10. **ICGN 关键失败/降级分支未测。** Cholesky 失败、二阶逆合成退化、收敛后越界/平场复核、协方差求逆失败均未执行；其中陈旧高 ZNCC 接受坏点、`UNCOMPUTED` 状态泄漏和全 NaN 协方差向 UQ 传播都可能造成静默错误。
11. **真实标定最常见的退化几何未测。** 共面/共线靶点 DLT 失败、相机中心重合/在无穷远、奇异 viewing ray、全部权重为零、非线性三角化不收敛均缺测试；Umeyama 反射修正也未触发，存在静默左右手系翻转风险。
12. **validator 的负例核心覆盖不足。** `validate_file` 仍有 39 条关键语句未覆盖，包括非法 schema 版本、未知 hash/role/shutter、畸变参数长度错误和 strict 模式缺协方差；如果这些分支漂移，损坏容器可能被错误接受。
13. **二阶形函数只完成内核，未完成产品接线。** 2D pipeline 仍走一阶，立体匹配对 `shape_order != 1` 明确报错；不能把“仓内有二阶函数”表述成 2D/3D 全链已使用二阶。

### P1：严重影响可用性、鲁棒性或审计可信度

1. **AOI 是孤立数据类。** `PolygonAOI` 未接入 pipeline，且不支持 outer/hole、逐帧遮挡和裂纹边界工作流。
2. **大位移/遮挡/断帧恢复不足。** 缺可靠性引导传播、特征全局重定位、断帧恢复和不连续模型。
3. **GUI 名称与实际能力不匹配。** viewer 不打开结果、不绘场、不切帧，只做依赖检查；不能称为可用桌面查看器。
4. **FEA 交付低于 S4 原门禁目标。** 实际只有内存三角网格投影，没有开放文件导入、坐标配准、同滤波链、归一化残差和真实 FE 案例。
5. **性能架构不可扩展。** 单线程 NumPy、无多核/GPU/断点续算；正常规模序列的完成时间没有正式 benchmark。
6. **跨机确定性未验证。** 当前证据仅支持同机重复，不能承诺跨 BLAS、CPU、OS 的 `<1e-4 px` 一致性。
7. **证据台账陈旧且互相不同步。** 当前源码已有 S2/S3/S4 模块，但 `metrics.json` 仍记录 `stereo.match`、`pipeline.dic3d`、`uq`、`cli.validate` 不存在；早期 S4 smoke 报告也记录 `3 skipped`。在最终集成测试和指标台账统一前，不能用“测试很多”替代正式出口证据。
8. **3D 没有完整 CLI/文件输出。** Python 内核存在，但用户无法通过统一命令获得可验证、可归档的 3D 结果包。
9. **相关与滤波配置面过窄。** 缺 NSSD、4/6/8 阶插值旋钮、Uniform/Gaussian 子区权重、抗混叠低通和时间轴中值/平滑链；同一公开工况无法按竞品参数口径复现。
10. **缺工程/会话对象与虚拟引伸计对象。** AOI、坐标变换、检查器、逐帧摘要和量规布局不能作为一个可重用工程保存，跨试样复现实验设置困难。
11. **项目自有法律门形式上失败。** L-2 规定合理关键词命中必须写入 `legal/scan-allowlist.txt`，但该文件/目录不存在，`icgn.py` 中正常的断裂力学术语 `crack tip` 因而成为未登记命中。内容没有侵权风险，流程却不满足自己的 fail-closed 规则。
12. **持续合规门覆盖不全。** 畸变实现扫描只覆盖 `hl3.stereo`，未覆盖 S4 新增的 cli/viz/fea/gui；也没有源码门阻止未来误引 GPU 或相机 SDK。
13. **S4 测试密度严重不足。** CLI run 仅 `50%` 行/`44%` 分支覆盖，viz 主模块仅 `61%` 行/`54%` 分支，FEA 410 条语句只有 2 个用例；全局 `88%` 行覆盖被 S1–S3 的 633 个数值测试抬高。
14. **GUI 存在已确认的入口缺陷。** `viewer.py` 为 `0%` 覆盖；无 tkinter 时 `--help` 也返回 2，且 `python -m hl3.gui.viewer` 因缺 `__main__` 守卫而静默退出 0，与自身 usage 文本冲突。
15. **matplotlib 与 FEA 关键分支没有验证。** 唯一 viz 用例强制走 builtin 后端，matplotlib 保存与自动回退未执行；FEA 的 nearest/fill-nearest、退化网格校验也基本未执行。
16. **两个高价值模块处于“半接线”。** pipeline→`.hl3` 写入和二阶 ICGN→pipeline 都缺最后连接；继续扩展新子系统会扩大接口债务。

### P2：不会立刻算错，但显著增加使用与维护成本

1. 图像原生入口主要是 `.npy/.npz/.pgm/.pnm`；PNG/TIFF 依赖 Pillow，彩色图不自动转灰。
2. 可视化缺图像底图、等值线、曲线探针、多视口、动画和模拟量/FEA 叠加。
3. 缺 CSV/ASCII/STL/MATLAB/VTK/视频等常用互操作导出，通用场结果也没有稳定的单位/坐标系声明。
4. 只有 Ubuntu/Linux CI，无 Windows/macOS 数值、路径、安装和卸载验证。
5. 包仍标记 `0.0.1.dev0 / Pre-Alpha`，无签名发布、版本迁移承诺或兼容政策。
6. 缺刚体去除、3-2-1/CAD 对齐和单位/坐标系防错工作流。
7. 缺报告模板、签字 PDF、GPG 字段强制检查和一键复算清单。
8. 缺极/柱坐标、变换管理与撤销、热应变/热膨胀扣除、逐帧结果表和进度/剩余时间。
9. Pillow、hdf5plugin 被软导入但未在 extras/SBOM 声明；viridis 的 CC0 归属只在 docstring，缺统一 `THIRD-PARTY/NOTICE` 资产。
10. `hl3.gui` 的 Apache-2.0 社区骨架与 README 中“后续商业 GUI 层”共用自然语言标签，未来 open-core 许可边界容易混淆。
11. SPDX 头只覆盖 37/54 个受扫文件；根许可证有效，但逐文件可追溯性不一致。
12. README 的“尚未实现”表已落后于源码；更新时必须把 GUI 写成 AOI 侧车+依赖探针、FEA 写成几何投影，避免能力高报。
13. `770 POI-solves/s` 的复引未附完整硬件清单；只能作为 4 vCPU、无 GPU 云主机上的非正式趋势，不能作为竞品吞吐比较。
14. `pytest-cov` 未进入 test extra，CI 没有覆盖率门；新增大量产品代码时，全局测试仍可能保持“全绿”而关键入口无人执行。
15. 没有共享 fixture 层；合法 `.hl3` 与真实图像样本若在各测试重复构造，会增加负例矩阵长期维护成本。

## 6. 不建议继续做的（S5/S6）和建议用户下一步

### 现在不建议继续 S5：GPU 吞吐

- 当前瓶颈不是“算得不够快”，而是“真实标定、3D 应变、UQ 正确性、结果归档和公开基准尚未闭合”。先 GPU 化会把未充分验证的数学更快地放大。
- 本环境只有 4 vCPU、无 GPU，无法完成多 GPU parity、吞吐边界和同机竞品比较。任何“超过 VIC/OpenCorr”的性能说法都不会因此获得合法证据。
- 在 CPU 规范实现、Challenge 基线和逐点 parity 门稳定前，不应投入 S5。

### 现在不建议继续 S6：采集与实时

- S6 需要至少两家真实相机、硬触发源、同步/掉帧台架、SDK 许可审查、DAQ/试验机和 24 h 浸泡环境；当前云端环境不具备。
- 仅继续扩展 `MockCapture` 会制造“接口看似完整”的假进度，不能证明实机同步、延迟、漂移或数据完整性。
- 3D 标定和结果链未闭合时接入实时采集，会让接口过早固化并增加返工。
- 显微/SEM 畸变仍是 `LEGAL-BLOCKED`，没有书面专利清查意见前不应借 S6 相机接入顺手扩展。

### 建议用户下一步（仅建议，不在本阶段实施）

1. **把当前版本冻结为“研发内核/影子复算版”**，不要切换正在交付、正式报告、3D 应变、实时或安全关键项目。
2. **先做一次 S1–S4 收口审计**：统一源码、测试、`metrics.json` 和阶段门状态，生成唯一可复跑的最终基线；优先覆盖真实读图、validator 负例、ICGN 失败降级、立体退化、GUI 无依赖退出和 FEA nearest/fill 分支。
3. **优先获取第三方证据**：下载并运行免费公开、附 MATLAB 分析脚本的 Stereo-DIC Challenge 1.0，同时运行 2D-DIC Challenge，并安排实体标定板、刚体台和拉伸试验；A5 当前缺口是未派工，不是数据不可得。
4. **先闭合正确性关键缺口**：真实标定+畸变+BA、曲面 3D 应变、重叠 POI 协方差、`Σ_cal` 和完整 `.hl3` 写出。
5. **再闭合最小产品链**：AOI 接 pipeline、可用结果查看器、报告 lint、常用导入导出和三平台 CI。
6. **只有上述门通过后再决定是否重启 S5/S6**；S5 必须配固定 GPU 基准机和 parity 协议，S6 必须配硬件在环实验室与 SDK 法务清单。
7. **在此之前的客户策略**：保留 VIC/MatchID 为生产主链，只把公开导出的灰度图复制给 HL3 做离线、非关键、可人工复核的影子计算。
8. **发布前收口法律流程**：补齐 L-2 allowlist、可选依赖/SBOM、第三方归属和全包源码守卫，并澄清社区 GUI 与未来商业层的命名/许可证边界。
