# VIC 客户今天切到 HL3 S4，会失去什么

## 先给结论

**不要把正在交付、要出正式报告、要控制硬件或要做 3D 应变的试验切到 HL3。** 当前 HL3 是 pre-alpha 的可审计计算内核，不是 VIC-2D/VIC-3D 的可替换产品。今天合理的用法只有：保留 VIC 为生产主链，把导出的灰度图复制给 HL3 做离线、非关键、影子复算。

以下 VIC 能力均只按公开产品资料描述，未在本环境独立验证；HL3 结论则按当前源码和测试逐项核对。

## Deal breakers（不能 ship experiment）

- [ ] **没有相机采集链。** HL3 没有相机 SDK、GenICam、曝光/帧率控制、硬触发、双目同步、掉帧处置、模拟量同步或试验机接口；`MockCapture` 只是 CI 假相机。换过去后，客户连“可靠地把试验拍下来”都做不到。**无软件内 workaround**；只能继续用 VIC-Snap/厂商采集软件，把图像事后导给 HL3。

- [ ] **真实 VIC-3D 工况没有可用标定。** 当前 3D 链吃的是用户已经给好的投影矩阵；仓内只有已知 3D 点的线性 DLT/合成针孔原型，没有标定板检测、Zhang 平面标定、束调整，也完全没有 Brown–Conrady 等镜头畸变。真实镜头一上场，合成针孔精度数字没有外推资格。**任何需要尺寸、形貌、W 位移可信度的 3D 交付都应停。**

- [ ] **没有 VIC-3D 的曲面应变产品链。** `Dic3DRun` 当前只给形貌和 `U/V/W`；3D pipeline 明确关闭 2D 应变，也没有切平面曲面应变实现。3D 结果没有 CLI 入口、没有端到端 `.hl3` 写出。客户若买 VIC-3D 是为了表面应变，切换后核心交付量直接消失。

- [ ] **没有实拍计量资格证据。** 当前亮眼数字来自解析/合成散斑、精确针孔或已知投影矩阵；没有 DIC Challenge 正式成绩、没有 Stereo Challenge 正式成绩、没有实体标定板、刚体台、拉伸机或跨实验室复现。`metrics.json` 仍把 S1/S2/S3 出口记为未关闭。**不能拿它做验收、保修、认证、失效判定或安全决策。**

- [ ] **实时、高速、疲劳触发和闭环全部没有。** 没有 VIC-Gauge 类实时虚拟引伸计、模拟量输出、在线全场、相位/峰谷触发、FFT/ODS，也没有延迟或 24 h 稳定性证据。碰撞、振动、疲劳、试验机闭环等项目切过来，实验设计本身就不成立。

- [ ] **桌面用户实际上没有 GUI。** `hl3.gui.viewer` 只检查 matplotlib/tkinter，然后明确“不启动交互 session”；它不打开结果、不画场、不切帧。AOI 目前只是一个单多边形 JSON 类，不是可画、可拖顶点、支持 outer/hole、并接入计算的 AOI 编辑器。依赖 VIC 桌面操作的技师今天无法完成工作。

- [ ] **生产结果包和正式报告链不存在。** `hl3 run` 只跑 2D，输出 `.npy/.npz + JSON`；它不生成公开 schema 的 `.hl3`，不写完整图像/标定/UQ/审计日志，也没有 GPG report lint、模板报告、签字版 PDF。schema 仍是 `1.0.0-draft.2`。对要求可追溯归档或合同报告的客户，这是直接的交付阻断。

- [ ] **现有 VIC 工程不能迁移。** HL3 不读 VIC 工程/专有格式，也不会逆向支持；现有 AOI、标定、变量、坐标系、应变设置、模拟通道和报告模板无法无损带过来。最多手工导出公开格式/原始图后重建分析。**不要在项目中途切。**

- [ ] **正常规模数据的处理时效没有保障。** 只有单线程 CPU NumPy 参考实现，无多核调度、GPU、断点续算或集群扩展。2D pipeline 的小型合成趋势仅约 `770 POI-solves/s`，没有正式吞吐 benchmark；VIC 公开宣传的是成熟并行产品。若客户要求当天处理大序列，HL3 可能从“慢”变成“根本排不完”。

- [ ] **没有厂商责任兜底。** 包版本是 `0.0.1.dev0 / Pre-Alpha`；只有 Linux CI，没有 Windows/macOS 发布验证、签名安装器、认证硬件清单、培训、热线、SLA 或现场应用工程师。工业客户切换等于自己承担软件、光学、硬件、计量和运维全部风险。

## Painful but workaround（能绕，但客户会明显退化）

- [ ] **2D 只能走工程师脚本/CLI。** workaround：预先导出两张以上灰度图，用 `hl3 run` 跑离线 2D，再自行保存参数和日志。代价是没有项目管理、预览、参数向导、队列、恢复和一键重算。

- [ ] **图像入口很窄。** 原生只保证 `.npy/.npz/.pgm/.pnm`；PNG/TIFF 要另装 Pillow，彩色图会被拒绝而不是自动转灰。workaround：在外部固定灰度转换、位深和文件命名，并自行证明转换没有改变计量结果。

- [ ] **AOI、孔洞和裂纹边界要外部处理。** 2D pipeline 只收规则网格或调用者给的点列；当前 AOI JSON 没接进 pipeline。workaround：用 Python 自己生成 POI、做点在多边形内筛选、维护孔洞/逐帧遮挡；一旦坐标错一位，没有 GUI 帮你发现。

- [ ] **大位移、遮挡、裂纹和断帧鲁棒性不足。** 有 FFT 粗种子和参考更新，但没有成熟的自动起点、可靠性引导传播、特征法全局重定位、裂纹不连续模型或自动恢复。workaround：缩小帧间位移、手工分段、频繁检查 status/ZNCC；代价是更多人工和累计参考误差。

- [ ] **没有刚体运动去除和工程坐标系工作流。** workaround：在 NumPy 中自行做刚体拟合、3-2-1/CAD 对齐和坐标变换，再把变换脚本纳入审计。HL3 不会替你防止单位或坐标系混用。

- [ ] **UQ 在常用重叠 subset 下会过度乐观。** 当前应变不确定度假设相邻 POI 独立；实测在 `step ≈ subset/4` 时预测仅为真实散布约 `0.55–0.58`，即标准差低估约 1.8 倍。workaround：用 `step ≥ 0.75·subset`、重复静态采集自行标定相关性，或干脆不把当前 CI 当置信声明；前两者会牺牲空间分辨率/试验时间。

- [ ] **3D 不确定度只算匹配项下界。** 没有标定参数协方差 `Σ_cal`，因此位置 sigma 默认假设标定已知无误。workaround：外部标定软件给协方差并自行传播；否则必须在报告中写明“不含标定误差”。

- [ ] **可视化只有单张 2D 标量格点图。** 可导 PNG，装 matplotlib 后可导 PDF/SVG，但没有图像底图、等值线、曲线探针、多视口、3D 表面、动画、模拟量叠加或 FEA 叠加。workaround：导出数组后自写 matplotlib/ParaView notebook。

- [ ] **FEA 不是闭环，只是几何小工具。** 当前 `hl3.fea` 只接受内存里的 2D 三角网格数组，做 DIC↔节点投影；没有 VTK/Exodus/Abaqus/ANSYS 导入、坐标配准、等效 VSG 过滤、z 残差报告、边界条件导出或真实 FE 案例。workaround：客户自己写网格读取、配准、过滤、比较和导出，HL3 只帮其中一小步。

- [ ] **导出生态几乎为空。** 没有 VIC 用户常用的 CSV/STL/MATLAB/工程网格/视频成品链。workaround：直接读 NumPy 数组自行转换；每个转换器都变成客户要维护和验证的代码。

- [ ] **没有模板报告和 GPG 向导。** subset、step、VSG、有效率、噪声底、空间分辨率、标定残差等不会被一个发布门强制齐全。workaround：团队维护自己的 notebook/checklist，并让第二个人审阅。

- [ ] **跨平台只是架构意图，不是今天的交付事实。** Python 代码可能能跑，但 CI 只有 Ubuntu；Windows/macOS 数值一致性、tkinter、文件路径、安装/卸载均未验证。workaround：锁定一套 Linux 容器，不要承诺桌面三平台。

## Nice to have（多数静态 2D 项目可暂时没有）

- [ ] 暗色主题、布局记忆、复制粘贴、绘图模板、4K 动画、视频编码和出版排版。
- [ ] FFT/FRF/ODS、相位平均、频闪/峰谷采样；对振动客户它们会从“nice”升级为 deal breaker。
- [ ] 多相机拼接、360° 测量、热像/温度场融合；对大型构件或多物理场客户同样会升级为 deal breaker。
- [ ] DMT/编码标记点跟踪、速度/加速度输出、虚拟引伸计面板。
- [ ] 显微镜/SEM、远心/特殊畸变、DVC 体相关；对应细分市场不能用 HL3 替代。
- [ ] 插件市场、项目内脚本结果回写、命令录制器、自包含 HTML 分享报告。
- [ ] 自动参数推荐、散斑质量向导、VSG 收敛向导、DL 大变形初值。
- [ ] 全局 FE-DIC、材料参数反演、裂纹 COD 专用工作流。

## HL3 advantages they would gain

- [ ] **无许可证锁和销售流程。** Apache-2.0 数值内核可直接审计、修改、部署；没有 PC 密钥、浮动许可服务器或席位等待。代价是同时没有商业支持兜底。

- [ ] **Python-first、无头、Linux 友好。** 数组就是 API，2D 可从 shell 批跑，适合 notebook、CI、容器和自动回归；不必把每个动作塞进桌面点击流程。

- [ ] **算法行为可追源码。** ICGN、状态码、应变张量、VSG、三角化和投影的实现及测试都可检查；失败点用明确 status/NaN 保留，不会为了画满云图静默补值。

- [ ] **同机确定性强。** CPU float64 路径、固定随机种子、确定性序列逻辑和参数快照适合做回归。注意：跨机器 `<1e-4 px` 仍未实测，不能把“同机重复”扩大成“全球可复现”。

- [ ] **应变后处理透明且便宜。** 工程、Green–Lagrange、Euler–Almansi、Hencky 张量和 PLS/VSG 都是公开实现；改变应变窗口可复用位移结果，不必重跑最贵的相关步骤。

- [ ] **质量诊断比只给彩色图更诚实。** 2D 有 status/ZNCC/迭代数，3D 有 Sampson、重投影、手性、位置 sigma、四路闭环和逐点拒绝原因；客户能看到“为什么这个点没有数”。

- [ ] **开放数据方向正确。** 有公开的 HDF5 schema 草案、纯 h5py 参考读取器和 `hl3 validate`，长期可降低数据锁定。**但今天 `hl3 run` 尚未写 `.hl3`，所以这是已落地组件优势，不是端到端产品优势。**

- [ ] **UQ 的假设被明说。** 即使当前重叠 POI 相关性尚未建模，HL3 至少把低估量级、适用条件和缺失的标定项公开；客户可以审计，而不是把一个 confidence 值当黑箱真理。

- [ ] **低依赖、容易做影子验证。** 核心只需 NumPy；客户可以在不碰现有 VIC 生产链的前提下，把公开导出的灰度图送进 HL3，逐步判断它是否值得未来迁移。

## 客户侧 go/no-go

- **Go（仅限影子试用）**：离线、单相机、灰度图、非安全关键、允许 Python、结果不作为合同唯一依据。
- **No-go**：任何新采集、任何正式 VIC-3D 应变、实时/高速/闭环、监管/认证报告、现有 VIC 工程无损迁移、GUI-only 团队。
- **切换门槛**：至少先补齐实机采集与标定、镜头畸变、3D 曲面应变、`.hl3` 端到端写出、真实 Challenge/实体试验证据、可用 GUI、报告 lint、三平台发布和支持责任。少一组，都只能叫研发内核，不能叫 VIC replacement。
